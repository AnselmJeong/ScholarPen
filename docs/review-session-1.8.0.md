# ScholarPen 1.8.0 — Review & Revision

2026-10-25. `peer-review-revision-system-plan.md`의 핵심 세션 흐름을 구현한 버전이다. 아래 구현·검증 범위와 아직 남은 범위를 구분한다.

## 사용 방법

1. 프로젝트를 열고 상단 **Review & Revision**을 선택한다.
2. **새 세션**에서 원고 범위, 가상 심사 또는 실제 심사 대응, GPT·Claude 모델, 최대 1/2회 수정과 답변 언어를 선택한다.
3. 실제 리뷰는 심사자별 원문을 붙여 넣거나 TXT/Markdown 파일로 가져온다. 편집자 결정문은 별도로 보관한다. 명시적으로 번호가 붙은 의견은 원문 범위를 유지하며 분리한다.
4. **원본 고정 · 세션 만들기**로 저장 완료 후 원본과 종속 그림·참고문헌을 복사한다. **심사·수정 시작**이 외부 모델 호출과 별도 작업본의 본문·표 수정을 시작한다.
5. 그림 요청이 있으면 그림마다 **교체 승인**, **현재 그림 유지**, **보류**를 선택한다. 교체 승인 후 준비한 PNG/JPEG/WebP/GIF를 가져오고 재개한다. 이 버전은 자동 이미지 생성 도구를 호출하지 않는다.
6. 완료 후 의견별 답변, 실제 변경, 원본/회차별 원고, 그림, 계획·검증 결과를 검토한다. **공유 패키지 저장**은 프로젝트의 `exports/`에 독립 폴더를 만든다.
7. **별도 사본에서 편집**은 원 프로젝트 옆에 독립 프로젝트를 만든다. 이전 검증·응답 위치는 수동 변경 이후 유효하지 않으며 `REVIEW-NOTICE.md`와 `.scholarpen/review-origin.json`에 기록한다. 봉인된 결과는 바뀌지 않는다.
8. 추가 자동 수정은 **최종 후보로 후속 세션 만들기**로 명시적으로 시작한다. 부모 세션과 선택한 최종 회차를 기록하며, 기존 세션의 회차 예산을 되돌리지 않는다.

## 구현한 보호 장치

- GPT reviewer는 `codex`, Claude reviser는 `anthropic` 구독 어댑터에 고정한다. 채팅 모델 변경이나 유료 API fallback을 사용하지 않는다.
- 전체 원고 문맥과 논문 기준표를 사용해 통합 계획을 먼저 작성한다. 수정 후 실제 적용된 변경으로 답변을 생성하고 GPT가 원고·누적 답변을 다시 검토한다.
- 실질 수정 슬롯을 시작 전에 저장하고 최대 2개로 제한한다. 조기 종료, 형식 복구 최대 2회, 영속적인 호출 결과/재시도 기록, 단일 writer 잠금, 취소 후 늦은 결과 차단을 구현했다.
- 입력과 완료 단계에 SHA-256을 기록한다. candidate는 별도 폴더에서 검사하고 원고·답변·검증을 한 회차로 봉인한다. 외부 변경 충돌에서는 덮어쓰지 않는다.
- 원본 JSON 바이트, 실제 의견 원문과 긴 답변을 잘라 저장하지 않는다. 인용·수식·각주 등 보호된 인라인 개체는 텍스트 패치로 변경할 수 없다.
- `reviews/`는 일반 파일 탐색·문맥·저장·협업 경로와 프로젝트 변경 알림에서 제외한다. 세션 엔진은 기존 live Y.Doc, 자동 reviewer, 원 프로젝트 메모리를 사용하지 않는다.
- 표 텍스트·헤더·캡션과 행 순서 패치를 지원한다. 숫자 변경은 명시적인 표 셀을 입력으로 삼는 합계·백분율 계산과 결과 일치를 요구한다. 숫자나 통계를 추측해 채우는 패치는 거절한다.
- 실제 이미지 픽셀은 4개씩 검토하고 이미지별 범위를 기록한다. 그림 승인에는 세션·회차·그림·입력·명세 해시를 연결한다. 가져온 파일은 새 이름으로 저장하고 재검토한다.
- 응답은 모든 원문 의견을 포함하고 실제 변경 ID를 참조한다. 후속 수정이 앞선 변경을 덮거나 되돌리면 유효한 누적 변경 증거를 갱신한다. 최종 후보는 동일 회차의 원고와 답변만 사용한다.
- 공유 패키지에는 원고·자료·답변·변경표와 파일 manifest를 넣는다. 내부 프롬프트·journal·저자용 보고서는 기본 제외한다.

## 명시적인 제한과 남은 작업

- 전체 context는 350,000자, 통합 단계 입력은 700,000자를 넘으면 자르지 않고 중단한다. 이는 토큰 한도가 아니라 보수적인 입력 크기 보호이며 긴 원고의 절별 검토·전역 통합은 후속 구현이다.
- 이미지는 각각 5 MB 이하의 PNG/JPEG/WebP/GIF를 전달한다. SVG/PDF 래스터화·대형 이미지 축소·패널 분할은 아직 없다. 지원하지 않는 그림과 외부/원격 의존성은 미검토 또는 unavailable로 기록해 품질 상태를 낮춘다.
- 명시적 파일 링크와 canonical bibliography를 복사한다. 임의 Quarto 확장, 원시 데이터·스크립트 의존 관계의 완전한 자동 수집과 외부 파일 동결은 아직 아니다.
- 표 분리/병합, 열 이동, 임의 통계 재분석은 지원하지 않는다. 지원 작업으로 표현되지 않는 변경은 보류한다. 수치 계산을 재현하는 검사는 입력 셀의 과학적 적합성을 독립적으로 증명하지 않으므로 GPT 검토와 저자 검토가 필요하다.
- 새로운 인용이나 문헌을 자동으로 검증·추가하는 기능은 이 엔진에 연결하지 않았다. 기존 인용을 보존하며 근거 없는 추가는 거절한다.
- 번호가 모호한 실제 심사의견은 원문 단위로 유지한다. 문장 의미에 의존하는 세부 요구 자동 분해·위치 재매칭 편집기는 후속 범위다.
- 수동 편집은 별도 프로젝트에서 한다. 전용 화면에서 부분 변경을 거절하고 연결 답변을 자동 재작성하는 기능은 없다. 기존 검증을 새 수동 사본에 자동 승계하지 않는다.
- 기본 내보내기는 ScholarPen JSON·자료·Markdown/JSON 답변 묶음이다. 별도 편집 프로젝트에서 기존 export 기능을 사용할 수 있지만 이 세션 화면의 자동 QMD/DOCX/PDF 렌더와 최종 페이지·행 매핑은 아직 없다.
- 서명·공증은 수행하지 않았다. 로컬 사용용 macOS arm64 빌드이며 공증된 공개 배포본으로 주장하지 않는다.

## 개발 재현

```bash
bun test src/bun/review src/bun/fs src/bun/collab/registry.test.ts src/bun/collab/storage.test.ts src/bun/collab/project-documents.test.ts src/bun/agent/mention-resolver.test.ts src/shared/collab/revision-log.test.ts
bunx tsc --noEmit
bun run build:release
# 실제 구독을 사용한다. 합성 데이터만 전달하고 .review-smoke/에 기록한다.
bun scripts/smoke-review-session.ts --live
```

주요 구현은 `src/bun/review/`, `src/shared/review-session/`, `src/renderer/components/review/`에 있다. 기존 계획 문서는 변경하지 않았다.
